브랜딩 접수·관리 06. 문의 접수 + 관리자 페이지

방문자가 남긴 문의·신청을 저장하고, 나만 보는 관리자 페이지에서 확인·관리합니다. 여기서 가장 중요한 건 안전한 로그인(서버 검증)입니다.

⏱ 약 30분📥 입력 · 배포된 사이트(05)📦 결과물 · 접수 저장 + 안전한 관리자 페이지

🔐 가장 중요한 보안 원칙: 관리자 비밀번호를 웹페이지 코드 안에 넣으면 안 됩니다(누구나 '소스 보기'로 뚫립니다). 반드시 서버에서 검증하세요. 이 활동에서 그 방법을 배웁니다.

1문의 접수 폼 붙이기 (방문자용)

방문자가 이름·연락처·문의내용을 남기면 어딘가에 저장되게 만듭니다.

  • 가장 쉬운 방법 — 구글폼을 만들어 '문의' 버튼에 연결(무료·안전, 응답은 구글시트에 자동 저장).
  • 사이트 안에서 받고 싶다면 → 아래 프롬프트로 폼 + 저장(Supabase 등)을 붙입니다.
너는 웹 개발 도우미야. 내 사이트에 '문의·신청 폼'을 붙이고, 제출하면 데이터가 저장되게 해줘. - 받을 항목: 이름 / 연락처 / 관심 서비스 / 문의내용 / (개인정보 수집 동의 체크) - 저장 위치: (구글폼→구글시트) 또는 (Supabase 테이블) 중 내 상황에 맞게 추천하고 그대로 세팅 안내 - 제출 후 "접수됐습니다" 안내와, 나에게 알림(메일/문자)이 가게 하는 방법 - 개인정보는 꼭 필요한 것만 받고, 동의 체크 없이는 제출 안 되게 초보도 따라 하게 클릭 순서로 알려줘.
2관리자 페이지 만들기 (나만 보는 화면)

들어온 문의를 목록으로 보고, 상태(연락함/완료)를 체크하는 화면을 만듭니다.

너는 웹 개발 도우미야. 방금 만든 '문의 접수'를 내가 확인·관리하는 관리자 페이지를 만들어줘. [기능] 1) 들어온 문의를 최신순 목록으로 표시(이름·연락처·문의·접수일) 2) 각 문의에 상태 표시(대기 / 연락함 / 완료)와 메모 3) 검색/필터(기간·상태) 4) 개인정보라 화면은 나만 봐야 함 → 로그인(다음 3단계에서 '서버 검증'으로 안전하게) [중요] 지금은 화면만 만들고, 비밀번호는 코드에 넣지 마. 3단계에서 서버 검증으로 붙일 거야.
🎯 관리자 페이지 주소는 남들이 못 찾게 하고(메뉴에 노출 X), 검색엔진 색인도 막습니다(robots noindex). 하지만 "숨기는 것"은 보안이 아닙니다 — 진짜 잠금은 3단계.
3안전한 로그인 — 서버 검증 (핵심)

관리자 페이지에는 개인정보(방문자 연락처)가 있으니, 반드시 안전하게 잠급니다.

⚠️ 이렇게 하면 안 됩니다 — 페이지 코드에 if(비번==="1234")처럼 넣기. 누구나 브라우저 '소스 보기'로 비번을 읽고 들어옵니다. 흔한 실수예요.
내 관리자 페이지 로그인을 '서버 검증' 방식으로 안전하게 만들어줘. (클라이언트 비번 금지) [해줘] 1) 비밀번호는 페이지 코드가 아니라 '서버(예: Supabase Edge Function)의 환경변수/시크릿'에 저장 2) 로그인 시 입력한 비번을 서버로 보내 검증하고, 맞을 때만 데이터를 내려주기 (틀리면 401, 데이터는 애초에 브라우저로 안 내려오게) 3) 문의 데이터도 아무나 못 읽게 — DB 접근 권한(RLS/서비스키)로 서버에서만 읽기 4) 왜 이 방식이 안전한지 한 줄로 설명도 내 사이트가 (Netlify + Supabase / 다른 스택)인지 물어보고 그에 맞게 단계별로 안내해줘.
✅ 이 정도면 통과 — 관리자 비번이 페이지 소스에 없고(서버에만), 틀린 비번으로는 문의 데이터가 아예 안 보이면 안전합니다.
🤖 클로드에서 바로 이어 하기 →
📦 이 활동의 결과물 — 문의가 저장되고, 서버 검증으로 안전하게 잠긴 관리자 페이지. 이제 고객 문의를 놓치지 않고 관리합니다.
🎤 강사 팁 (강사 전용) — 이 활동의 진짜 목표는 "비번을 코드에 넣지 않는다" 한 가지입니다. 학생 대부분이 if(pw==="8808")식으로 만들려 하니 꼭 잡아 주세요. 개인정보(연락처)를 다루므로 수집 동의 체크·최소 수집도 강조하고, 실제 검증은 "틀린 비번 → 데이터 안 보임"으로 눈앞에서 시연하면 각인됩니다.
